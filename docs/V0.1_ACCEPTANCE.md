## 二、功能验收清单

- [ ] `ov_` 表、字段、索引和外键与 `src/db/schema.ts` 一致；旧库缺失列/索引会在启动时自动修补。
- [ ] `pnpm seed` 可重复执行并创建 Golden Path Workflow 和 Edges。
- [ ] Workflow Nodes/Edges 物化为 Plan、Task、Session，blocked Task 等待依赖。
- [ ] 多节点链路按依赖推进，依赖不满足时不会提前执行。
- [ ] Checkpoint 创建待处理 Decision，Run 进入 `awaiting_decision`。
- [ ] `approve`、`request_changes`、`reject`、`override`、`replan` 五种动作符合状态语义。
- [ ] Replan 新建递增 Plan 版本、supersede 旧对象并重置未完成任务；默认自动续跑。
- [ ] 面板 Agent 对话返回 202，回复写入 `ov_node_messages`。
- [ ] Artifact、Memory、独立 Direct Chat、Permission Policy、Budget 和监控告警不在当前主流程里。
- [ ] `POST /api/workflow-runs/:id/execute` 返回 202，重复活动执行返回 409。
- [ ] Session 使用 `POST /api/sessions/:id/start`；不存在旧 `/execute` 调用。
- [ ] SSE 发送 ready、`orvia.event` 与约 15 秒 heartbeat。
- [ ] `/health` 正常时返回 database ok、redis ok、runtime 与 revision3 version；本机 Redis 连不上时 API 拒绝启动。
- [ ] Workflow 面板展示执行日志，并在等待决策时可以提交 Decision。
- [ ] CI 定义执行 frozen install、typecheck、test 与全栈 `pnpm build`。

## 三、人工验收路径

1. 按需执行 seed（会先补齐缺失表），再启动 API 与控制台。
2. 执行 `curl http://127.0.0.1:4100/health`。
3. 执行 `curl -N 'http://127.0.0.1:4100/api/events/stream?projectId=1'`，观察 heartbeat。
4. 在 Workflow Builder 创建含 Edge 与 Checkpoint 的多节点 Workflow，并创建 Run。
5. 点击执行，确认调用返回 202；在 Workflow 面板观察节点进度和日志。
6. 对 Decision 在面板上逐项验收动作，至少一次通过 request_changes/replan 验证 Plan 版本递增。
7. 在画布上打开一个 Agent，发送指导并看到回复。

## 四、已知边界

完整 MVP 仍是单体、单主机 Pi；互不依赖的就绪节点可并行执行。Budget 在派发前原子预占。本阶段只验收本机双进程。多租户、本机 Redis 与监控告警已纳入实现；Kafka 不使用。仍排除：复杂模型
fallback/自动路由、Temporal/Kubernetes、生产级 Secret 与自动费用结算。Artifact Versions 与 Memory 已纳入本次验收。
